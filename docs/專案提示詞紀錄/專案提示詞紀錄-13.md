### 檢查名稱是否存在的 SQL 語句

假設你要檢查的資料表名稱列表是 `['sales_data', 'user_visits', 'marketing_campaign']`。

```sql
SELECT
  name
FROM tables
WHERE

```

#### 語句說明

1.  **`SELECT name`**: 只需要回傳已存在的資料表名稱。
2.  **`FROM tables`**: 針對你的資料表管理器 $\text{metadata}$ 表 (`tables`) 進行查詢。
3.  **`WHERE name IN (...)`**: 這是核心邏輯。`IN` 運算符會檢查 `name` 欄位的值是否匹配括號中提供的任何一個值。

2.  **建立 $\text{SQL}$ 查詢**：
      * `better-sqlite3` 推薦使用**參數綁定**（`?` 或具名參數 `:name`），以防止 $\text{SQL}$ 注入並處理字串轉義。

```typescript

import { Database } from 'better-sqlite3';

// 假設 filesToCheck 是從前端傳來的 ['sales_data', 'user_visits', 'marketing_campaign']

/**
 * 批量檢查資料表名稱是否已存在
 * @param db better-sqlite3 實例
 * @param tableNames 要檢查的名稱陣列
 * @returns 已存在名稱的陣列
 */
checkTableNamesExist(db: Database, tableNames: string[]): string[] {
    if (tableNames.length === 0) {
        return [];
    }
    
    // 建立參數佔位符 (e.g., '?, ?, ?')
    const placeholders = tableNames.map(() => '?').join(', ');

    // 完整的 SQL 語句
    const sql = `
        SELECT name
        FROM tables
        WHERE name IN (${placeholders})
    `;

    // 執行查詢，並將 tableNames 作為參數傳入
    const existingRecords = db.prepare(sql).all(...tableNames);

    // 將結果轉換為單純的名稱陣列
    return existingRecords.map(record => record.name);
}
```

#### 1\. 實現名稱提取工具函數

```typescript
// src/utils.tsx (新增或修改)

/**
 * 從檔名中移除副檔名，作為資料表的名稱。
 * 範例: "users.csv" -> "users"
 * 範例: "data.v1.json" -> "data.v1"
 * @param filename 包含副檔名的檔案名稱
 * @returns 移除副檔名後的純淨名稱
 */
export const getTableNameFromFile = (filename: string): string => {
  // 尋找最後一個點 ('.') 的位置
  const lastDotIndex = filename.lastIndexOf('.');
  
  // 如果沒有找到點，或者點是第一個字元 (例如 '.DS_Store' 這種情況，雖然不常見)，
  // 則返回原始名稱。
  if (lastDotIndex === -1 || lastDotIndex === 0) {
    return filename;
  }
  
  // 返回從開頭到最後一個點之前的子字串
  return filename.substring(0, lastDotIndex);
};
```

## Gemini 回答 資料表上傳對話框-重構
這是很棒的重構機會！您目前的程式碼混雜了三個不同目的的狀態：

1.  **`selectedFiles`**: 僅用於儲存原始檔案，並作為 `useEffect` 的 $\text{debounce}$ 來源。
2.  **`filesStatus`**: 用於儲存帶有衝突檢查和使用者操作的最終狀態。
3.  **檔案處理邏輯**: $\text{preprocessFiles}$ 仍然針對 `File[]` 而不是 `FileStatus[]` 進行過濾。

最佳的重構是**移除 `selectedFiles` 狀態**，讓 `filesStatus` 成為唯一的真理來源（Single Source of Truth），並將檔案處理邏輯與狀態初始化合併。

-----

### 合併與重構後的 $\text{UploadDataTableDialog.tsx}$

我將主要優化以下幾點：

1.  **移除多餘狀態**：移除 `selectedFiles`，讓 `filesStatus` 承擔所有責任。
2.  **簡化處理流程**：將檔案過濾、名稱提取和 `FileStatus` 建立合併到一個流程中。
3.  **修復 ID 邏輯**：使用**包含副檔名的檔案名稱**作為 `FileStatus` 的唯一 ID (`id`)，以滿足您的顯示需求。
4.  **修復 `handleUpload` 邏輯**：單檔案導航時應使用 `filesStatus[0].file`。

## Gemini 回答 後端計算資料表檔案新名稱
這是一個關鍵的後端邏輯點。當前端傳入的檔案名稱（純淨名稱，例如 `'users'`）與資料庫中現有的表格名稱衝突，並且使用者選擇了 **自動更名 (`rename`)** 時，後端就需要負責計算出一個新的、不重複的名稱（例如 `'users_1'`、`'users_2'` 等）。

由於您的資料表 $\text{metadata}$ 是儲存在 $\text{SQLite}$ 的 `tables` 表中，我們可以利用 $\text{SQL}$ 的查詢能力來高效地完成這個任務。

-----

### 後端計算新名稱的 SQL 策略

核心策略是：**查詢所有以原始名稱開頭的現有表格，找出最大的序號，然後加 $1$。**

#### 1\. SQL 查詢目標

假設原始純淨名稱為 `original_name` (例如 `'sales'`)。我們需要查詢所有名稱看起來像 `sales`、`sales_1`、`sales_2` 等的表格。

```sql
SELECT
  name
FROM tables
WHERE
  -- 匹配 'sales' 本身
  name = $original_name
  OR
  -- 匹配 'sales_N' 格式，其中 N 是數字
  name LIKE $pattern_prefix || '[0-9]%' ESCAPE '\'
ORDER BY
  name DESC;
```

> **注意**：
>
>   * `$original_name` (例如 `'sales'`) 和 `$pattern_prefix` (例如 `'sales\_'`) 都是 $\text{SQL}$ 參數。
>   * `ESCAPE '\'` 是必要的，因為我們需要將 `\_` 視為字面上的底線，而不是 $\text{LIKE}$ 運算符中的單個字符萬用字元。
>   * $\text{SQLite}$ 不支援 $\text{REGEX}$，所以我們需要使用 `LIKE` 運算符，並依賴後端程式語言 (例如 $\text{TypeScript}$) 進行最終的數字提取和計算。

#### 2\. TypeScript/JavaScript 邏輯實現 (使用 `better-sqlite3`)

以下是在您的 $\text{Electron}$ 後端（例如 `DatabaseManager.cts` 或 `TableManager.cts`）中，實現此邏輯的步驟：

```typescript
// electron/models/TableManager.cts (示例)
import { Database } from 'better-sqlite3';

/**
 * 當發生名稱衝突且需要 'rename' 時，計算一個新的不重複名稱。
 * @param db better-sqlite3 實例
 * @param originalName 發生衝突的純淨名稱 (例如: 'users')
 * @returns 新的、不重複的表格名稱 (例如: 'users_1' 或 'users')
 */
export function getNewTableName(db: Database, originalName: string): string {
    // 步驟 1: 建立查詢參數
    // \_\ 是字面上的底線，因為 LIKE 中的 '_' 是單個字符萬用字元。
    const patternPrefix = originalName + '\\_'; 
    
    // 建立 SQL 查詢
    // 我們使用 WHERE name GLOB... 來更好地匹配起始字符並檢查數字結尾
    // 這裡我們假設使用更簡單的 LIKE 配合後端邏輯來處理
    const sql = `
        SELECT name
        FROM tables
        WHERE 
          name = @originalName 
          OR 
          name LIKE @patternPrefix || '%'
    `;

    // 步驟 2: 執行查詢並獲取所有潛在衝突的名稱
    const existingNames = db.prepare(sql).all({ 
        originalName: originalName, 
        patternPrefix: patternPrefix 
    }).map(row => row.name) as string[];

    // 步驟 3: 計算下一個可用的序號 (TypeScript/JavaScript 邏輯)
    let maxSuffix = 0;
    
    // 定義匹配 'name_N' 結構的正規表達式
    // 它匹配以 originalName + '_' 開頭，後面跟著一個或多個數字 (N) 的字串
    const regex = new RegExp(`^${originalName}_(\\d+)$`);

    for (const name of existingNames) {
        if (name === originalName) {
            // 如果原始名稱存在，最大序號至少為 0
            maxSuffix = Math.max(maxSuffix, 0); 
            continue;
        }
        
        const match = name.match(regex);
        
        if (match && match[1]) {
            // 提取匹配到的數字部分 (match[1])
            const suffix = parseInt(match[1], 10);
            maxSuffix = Math.max(maxSuffix, suffix);
        }
    }
    
    // 步驟 4: 計算新的名稱
    const newSuffix = maxSuffix + 1;

    // 原始名稱不存在，但 foundNames 可能包含 'name_N'，這表示 maxSuffix >= 0
    // 如果 originalName 存在 (maxSuffix >= 0)，我們應該返回 originalName_1
    // 如果 originalName 和 name_N 都不存在，existingNames 為空，maxSuffix = 0，newSuffix = 1。

    // 由於您的衝突檢查邏輯已經在前端執行過了，如果使用者選擇 'rename'，
    // 則 originalName 必然已與資料庫中的表格衝突 (或者與另一個新上傳的檔案衝突，但後端只關心 DB 衝突)。
    // 因此，我們總是需要加上序號。
    
    // 最終邏輯：如果 existingNames 不為空，則計算出下一個序號
    if (existingNames.length === 0) {
        // 這不應該發生，因為我們假設在呼叫這個函數時已經確認了衝突。
        // 但作為安全備份，如果沒有衝突，則返回原始名稱
        return originalName; 
    }

    // 返回：原始名稱 + '_' + (maxSuffix + 1)
    return `${originalName}_${newSuffix}`;
}
```
