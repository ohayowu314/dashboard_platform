# 儀表板草稿系統實現計劃 (v0.3.0)

## 一、背景與目標

為了解決 React Router state 在頁面跳轉（如進入區塊編輯器）時狀態傳遞複雜且易錯的問題，引入基於檔案的草稿（Draft）機制。這確保了編輯過程中的狀態始終持久化在硬碟上，即便頁面重新整理或發生錯誤，編輯進度也不會遺失。

## 二、流程設計

### 1. DashboardEditorPage (主編輯器)
- **進入編輯器**：
  1. 調用 `getDashboardDraft(id)`。
  2. 後端檢查 `draft.json` 是否存在。
  3. 若存在則載入；若不存在則從 `config.json` 複製一份建立 `draft.json` 後載入。
- **編輯過程中**：
  - 任何異動（標題、描述、佈局、區塊增刪）立即調用 `saveDashboardDraft(id, config)`。
- **按鈕行為**：
  - **取消**：調用 `deleteDashboardDraft(id)`，拋棄所有變更，返回 `DashboardViewPage`。
  - **儲存**：調用 `updateDashboard(id, config)`。此時同時更新 `config.json` 與 `draft.json`（保留草稿供繼續編輯）。
  - **完成**：調用 `updateDashboard(id, config)` 並接著調用 `deleteDashboardDraft(id)`，隨後返回 `DashboardViewPage`。

### 2. ChartEditorPage (區塊編輯器)
- **進入編輯器**：
  - 調用 `getDashboardDraft(id)`，並根據 `blockId` 從 `blocks` 陣列中提取對應的 `config`。
- **儲存區塊**：
  - 將修改後的區塊 config 合併回 `DashboardConfig`。
  - 調用 `saveDashboardDraft(id, updatedDashboardConfig)`。
  - 返回 `DashboardEditorPage`。

### 3. DashboardViewPage (檢視器)
- 始終讀取 `config.json` (透過現有的 `getDashboardById`)。

## 三、修改清單

### 後端 (IPC & Services)
1. **`electron/services/DashboardService.cts`**：
   - 實作 `getDashboardDraft`, `saveDashboardDraft`, `deleteDashboardDraft`。
2. **`electron/ipc/DashboardAPIHandlers.cts`**：
   - 註冊對應的 IPC 處理函數。
3. **`electron/preload.cts` & `src/preload.d.ts`**：
   - 暴露新 API 給前端。

### 前端 (Pages)
1. **`src/pages/DashboardEditorPage.tsx`**：
   - 重構載入與儲存邏輯。
   - 移除對 `location.state` 的依賴。
2. **`src/pages/ChartEditorPage.tsx`**：
   - 重構載入與儲存邏輯（從 Draft 讀寫）。
   - 移除對 `location.state` 的依賴。

## 四、驗證步驟
1. 進入儀表板編輯，隨意移動區塊，然後手動重新整理網頁。確認重新整理後位置仍是調整後的狀態（因為讀取了草稿）。
2. 在區塊編輯器修改標題並儲存。返回主編輯器確認標題已更新。
3. 點擊「取消」，確認所有變更被拋棄。
4. 點擊「完成」，確認變更永久儲存至正式設定並刪除草稿。
